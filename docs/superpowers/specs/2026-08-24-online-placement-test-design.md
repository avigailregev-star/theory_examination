# מבחן התאמה לתאוריה — הפיכה לשירות אונליין עם שמירת נתונים משותפת

תאריך: 2026-08-24

## מטרה

הקובץ `Dimona-Theory-Placement-Standalone.html` הקיים הוא מבחן התאמה עצמאי הפועל
כולו בדפדפן, שומר תוצאות ב-localStorage מקומי, וללא כתובת אינטרנט משלו. המטרה:
להפוך אותו לשירות שתלמידים והורים יכולים לגשת אליו **מהבית**, כשהתוצאות
נשמרות במקום משותף אחד שהצוות יכול לנהל מכל מכשיר.

## מחוץ לתחום (Non-goals)

- אין דרישה למערכת התחברות אישית למנהלים (`admin`) — סיסמה משותפת אחת מספיקה כרגע.
- אין דרישה לדומיין קבוע — כתובת חינמית זמנית של Vercel (`*.vercel.app`) מספקת.
- אין שינוי בלוגיקת המבחן עצמו (בנק שאלות, אבחון 7 רמות, שיבוץ ל-4 רמות
  קונסרבטוריון, טיפול נפרד בגיטרה) — הכל נשאר כפי שהוא, רק יעד השמירה משתנה.
- אין דרישה לגיבוי אוטומטי לענן/ייצוא CSV חדש — Supabase עצמו הוא מקור האמת,
  וניתן להמשיך ולייצא ידנית מהמסך הקיים בעתיד אם יידרש.

## ארכיטקטורה

```
דפדפן תלמיד/הורה                 Vercel (hosting + serverless)              Supabase (חשבון חדש, נפרד)
──────────────────                ──────────────────────────────            ───────────────────────────
קובץ HTML הקיים  ── מבחן בדפדפן
                  ── POST /api/submit ──────────▶  בודק תפוסת קבוצה (≤8)
                                                    ומכניס תוצאה              INSERT INTO results
דפדפן מנהל
                  ── POST /api/admin (סיסמה) ────▶  שולף/מעדכן תוצאות        SELECT/UPDATE results
```

- **Frontend**: אותו קובץ HTML קיים כמעט ללא שינוי חזותי. הפונקציות שכיום
  קוראות/כותבות ל-`localStorage` מוחלפות בקריאות `fetch` לשתי נקודות הקצה
  למטה. שאר הקוד (מבחן, ניקוד, אבחון, UI) לא משתנה.
- **Backend**: שתי Vercel Serverless Functions בלבד:
  - `api/submit.js` — ציבורי, ללא סיסמה. מקבל תוצאת מבחן + מועד שיעור נבחר.
  - `api/admin.js` — מוגן בסיסמה משותפת (נבדקת מול משתנה סביבה ב-Vercel).
    מחזיר/מעדכן תוצאות ותפוסת קבוצות.
  שתי הפונקציות הן היחידות שמחזיקות את מפתח ה-Service Role של Supabase.
  אין לו גישה מהדפדפן בשום שלב.
- **Database**: פרויקט Supabase **חדש ונפרד** (לא זה שמשמש את kuns_pro), טייר
  חינמי. טבלה אחת `results`. RLS חסום לגמרי לגישה ציבורית — כל קריאה/כתיבה
  עוברת דרך שתי הפונקציות בלבד, שמחוברות עם ה-Service Role (עוקף RLS).
- **Hosting**: Vercel מחובר לריפו הקיים ב-GitHub (`avigailregev-star/theory_examination`).
  כל `push` ל-`main` מפרסם אוטומטית לכתובת `*.vercel.app`.

## מבנה נתונים (Supabase)

טבלה `results`:

| עמודה | סוג | הערות |
|---|---|---|
| `id` | uuid, PK, default `gen_random_uuid()` | |
| `created_at` | timestamptz, default `now()` | |
| `student_name` | text | |
| `instrument` | text | כולל טיפול נפרד בגיטרה כפי שקיים היום |
| `diagnosed_level` | int | אחת מ-7 הרמות הקיימות באבחון |
| `placement_level` | int | אחת מ-4 רמות הקונסרבטוריון |
| `lesson_slot_id` | text | מזהה המועד שנבחר |
| `raw_answers` | jsonb | תשובות גולמיות, לצורך בקרה/דיבוג עתידי |

טבלת `lesson_slots` (למעקב תפוסה):

| עמודה | סוג | הערות |
|---|---|---|
| `id` | text, PK | מזהה קבוע לכל מועד/רמה |
| `capacity` | int | ברירת מחדל 8 |
| `booked_count` | int | מתעדכן אטומית עם כל הגשה מוצלחת |

בדיקת התפוסה ועדכונה מתבצעות בטרנזקציה אחת בתוך `api/submit.js` (או פונקציית
Postgres ב-Supabase), כדי למנוע מצב מרוץ שבו שני תלמידים חורגים מ-8 בו-זמנית.

## נקודות קצה

### `POST /api/submit`
- קלט: פרטי תלמיד, תוצאת אבחון, `lesson_slot_id` נבחר.
- לוגיקה: בתוך טרנזקציה — בודק `booked_count < capacity` עבור המועד, אם כן
  מכניס שורה ל-`results` ומעלה `booked_count` ב-1.
- אם המועד התמלא: מחזיר 409 + רשימת מועדים פנויים מעודכנת לאותה רמה.
- הצלחה: מחזיר אישור לתלמיד.

### `POST /api/admin`
- קלט: סיסמה + פעולה (`list` / `export` / עדכון שיבוץ ידני).
- בדיקת סיסמה מול משתנה סביבה `ADMIN_PASSWORD` ב-Vercel. סיסמה שגויה → 401.
  הגבלת קצב פשוטה (counter בזיכרון) כדי למנוע ניחושים אוטומטיים חוזרים.
- הצלחה: מחזיר תוצאות/תפוסה עבור מסך הניהול הקיים בקובץ.

## טיפול בשגיאות

- **אובדן חיבור באמצע המבחן**: לא רלוונטי — המבחן עצמו רץ כולו בדפדפן ללא
  תלות ברשת; רק ההגשה הסופית דורשת חיבור.
- **כשל ברשת בזמן שליחת התוצאה הסופית**: התוצאה נשמרת זמנית גם ב-`localStorage`
  המקומי (כמו היום), עם כפתור "נסה שוב", כך שתלמיד לא מאבד מבחן שהשלים.
- **קבוצה התמלאה בדיוק בזמן ההגשה**: כפי שמתואר למעלה — 409 + רשימת מועדים
  מעודכנת, התנהגות דומה למה שכבר קיים היום בקובץ.
- **סיסמת מנהל שגויה**: הודעת שגיאה רגילה + הגבלת קצב בסיסית.

## פריסה (Deployment)

1. יצירת חשבון Supabase חדש ונפרד, פרויקט חדש, טייר חינמי.
2. יצירת הטבלאות לעיל (SQL migration אחד).
3. חיבור הריפו הקיים (`theory_examination`) ל-Vercel.
4. הגדרת משתני סביבה ב-Vercel: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
   `ADMIN_PASSWORD`.
5. Push → פריסה אוטומטית → קבלת כתובת `*.vercel.app`.

צעדים 1 ו-3 דורשים יצירת חשבונות/הרשאות בפועל על ידי בעלת הפרויקט (לא ניתן
לבצע אותם מטעמה) — ילוו בהנחיה מפורטת בזמן הביצוע.

## בדיקות

ידניות בלבד, מתאים להיקף הפרויקט:
- שליחת תוצאה מלאה כ"תלמיד" ואימות הופעתה במסך הניהול.
- תרחיש קבוצה מלאה (8/8) ווידוא הודעת השגיאה + הצעת מועדים חלופיים.
- כניסה למסך ניהול עם סיסמה נכונה ושגויה.
- בדיקה שהמבחן עצמו (שאלות, ניקוד, אבחון) לא השתנה בהתנהגותו.
